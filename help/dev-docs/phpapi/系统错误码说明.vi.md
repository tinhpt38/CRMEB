# Mô tả mã lỗi hệ thống

## 📋 Đặc tả mã lỗi

### Thông số chung
- **Định dạng**: Mã lỗi 3 chữ số + thông báo lỗi
- **Phân loại**: Phân loại theo mô-đun và loại lỗi
- **Phản hồi thống nhất**: Tất cả lỗi được trả về thông qua xử lý ngoại lệ thống nhất

### Định dạng phản hồi
```json
{
    "status": 400,
    "msg": "参数错误",
    "data": null,
    "time": "2024-01-17 15:30:00"
}
```

## 🛠️ Lỗi xử lý các phương pháp hay nhất

### Xử lý lớp điều khiển
```php
try {
    // 业务逻辑处理
    $result = $service->doSomething($params);
    return $this->success($result);
} catch (ApiException $e) {
    // 捕获业务异常
    return $this->fail($e->getMessage(), $e->getCode());
} catch (\Exception $e) {
    // 捕获系统异常
    Log::error('系统异常: ' . $e->getMessage());
    return $this->fail('系统繁忙，请稍后重试', 500);
}
```

### Lớp dịch vụ ném ra một ngoại lệ
```php
// 业务验证失败时抛出异常
if (!$user) {
    throw new ApiException('用户不存在', 1201);
}

if ($stock < $quantity) {
    throw new ApiException('商品库存不足', 2001);
}
```

### Lớp ngoại lệ tùy chỉnh
```php
class ApiException extends \Exception
{
    public function __construct($message = "", $code = 400, \Throwable $previous = null)
    {
        parent::__construct($message, $code, $previous);
    }
}

class AdminException extends ApiException
{
    // 管理端专用异常
}
```

## 📝 Thông số kỹ thuật bảo trì mã lỗi

### Thêm mã lỗi
1. Chọn dãy mã lỗi thích hợp
2. Ghi lại mã lỗi và mô tả trong tài liệu này
3. Thêm ánh xạ mã lỗi trong xử lý ngoại lệ tương ứng

### Nguyên tắc sử dụng mã lỗi
1. **Tính duy nhất**: Mỗi mã lỗi tương ứng với một tình huống lỗi duy nhất
2. **Dễ đọc**: Thông báo lỗi rõ ràng và dễ hiểu
3. **Tính nhất quán**: Các lỗi cùng loại sử dụng cùng một dải mã lỗi
4. **Khả năng mở rộng**: Dự trữ không gian mã lỗi cho việc mở rộng chức năng tiếp theo

## 🔍 Hướng dẫn khắc phục sự cố

###Các bước khắc phục lỗi thường gặp
1. **Xác nhận mã lỗi**: Xác định danh mục sự cố dựa trên mã lỗi được trả về
2. **Xem nhật ký**: Kiểm tra bản ghi nhật ký của logic nghiệp vụ liên quan
3. **Xác minh tham số**: Kiểm tra xem tham số yêu cầu có đáp ứng yêu cầu không
4. **Kiểm tra trạng thái**: Xác nhận xem trạng thái của dữ liệu liên quan có bình thường không
5. **Môi trường thử nghiệm**: Tái tạo sự cố và gỡ lỗi trong môi trường thử nghiệm

### Thông số ghi nhật ký

// 记录错误日志
