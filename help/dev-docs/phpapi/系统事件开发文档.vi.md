# Tài liệu phát triển sự kiện hệ thống CRMEB

## 1. Tổng quan về cơ chế sự kiện

CRMEB 后端系统采用**事件驱动架构**，通过事件机制实现模块间的解耦和通信。事件系统允许在不直接依赖的情况下，实现不同模块间的交互和业务逻辑扩展。

### 1.1 Khái niệm cốt lõi

- **Sự kiện**: Các hành động hoặc thay đổi trạng thái cụ thể xảy ra trong hệ thống, chẳng hạn như tạo đơn hàng, đăng ký người dùng, v.v.
- **Listener**: Lớp lắng nghe các sự kiện cụ thể và thực thi logic xử lý tương ứng
- **Trình kích hoạt sự kiện (Trình kích hoạt)**: Gọi một sự kiện tại một điểm logic nghiệp vụ cụ thể để thông báo cho người nghe có liên quan thực hiện

##2. Kiến trúc hệ thống sự kiện

### 2.1 Định nghĩa giao diện Listener

Tất cả trình nghe phải triển khai giao diện `crmeb\interfaces\ListenerInterface`, giao diện này xác định phương thức xử lý sự kiện thống nhất:

```php
<?php
namespace crmeb\interfaces;

interface ListenerInterface
{
    public function handle($event): void;
}
```

### 2.2 Cấu hình và đăng ký sự kiện

Các sự kiện được xác định và đăng ký thông qua tệp `app/event.php`, tệp này trả về một mảng chứa cấu hình sự kiện:

```php
return [
    'bind' => [], // 事件绑定
    'listen' => [ // 事件监听
        'EventName' => [
            'Listener1::class',
            'Listener2::class',
        ],
    ],
];
```

**Cấu hình ví dụ**:
```php
return [
    'listen' => [
        'HttpEnd' => [\app\listener\http\HttpEndListener::class], //HTTP请求结束回调事件
        'UserRegisterListener' => [\app\listener\user\RegisterListener::class], //用户注册后置事件
        'OrderCreateAfterListener' => [\app\listener\order\OrderCreateAfterListener::class], //订单创建后置事件
        // 更多事件...
    ],
];
```

## 4. Kích hoạt và xử lý sự kiện

### 4.1 Phương thức kích hoạt sự kiện

Các sự kiện được kích hoạt thông qua hàm `event()`, đây là một hàm toàn cục do khung ThinkPHP cung cấp:

```php
// 触发事件
event('EventName', $eventData);

// 示例：触发订单创建事件
event('OrderCreateAfterListener', [$order, $group, $uid, $key, $combinationId, $seckillId, $bargainId]);
```

### 4.2 Quá trình xử lý sự kiện

1. **Kích hoạt sự kiện**: Kích hoạt các sự kiện cụ thể thông qua hàm `event()` trong logic nghiệp vụ
2. **Phân phối sự kiện**: Hệ thống tìm kiếm danh sách người nghe tương ứng dựa trên tên sự kiện.
3. **Thực thi trình nghe**: Gọi lần lượt phương thức `handle()` của từng trình nghe và truyền dữ liệu sự kiện
4. **Xử lý nghiệp vụ**: Người nghe thực hiện logic nghiệp vụ của riêng họ, chẳng hạn như xử lý dữ liệu, gửi tin nhắn, v.v.
5. **Xử lý hoàn tất**: Sau khi tất cả các trình nghe được thực thi, quá trình xử lý sự kiện sẽ kết thúc

## 5. Triển khai trình nghe

### 5.1 Các bước tạo Listener

1. **Tạo lớp người nghe**: Tạo lớp người nghe tương ứng trong thư mục `app/listener/`
2. **Triển khai giao diện**: triển khai giao diện `crmeb\interfaces\ListenerInterface`
3. **Viết logic xử lý**: Viết logic xử lý sự kiện trong phương thức `handle()`
4. **Đăng ký Listener**: Đăng ký Listener trong tệp `app/event.php`

### 5.2 Ví dụ triển khai Listener

#### 5.2.1 Trình nghe sự kiện tạo đơn hàng

```php
<?php
namespace app\listener\order;

use app\jobs\notice\PrintJob;
use app\jobs\ProductLogJob;
use app\jobs\UnpaidOrderCancelJob;
use app\jobs\UnpaidOrderSend;
use app\services\order\StoreOrderCreateServices;
use app\services\order\StoreOrderStatusServices;
use crmeb\interfaces\ListenerInterface;
use crmeb\services\CacheService;
use crmeb\services\SystemConfigService;
use crmeb\utils\Arr;

/**
 * 订单创建后置事件
 * Class OrderCreateAfterListener
 * @package app\listener\order
 */
class OrderCreateAfterListener implements ListenerInterface
{
    public function handle($event): void
    {
        [$order, $group, $uid, $key, $combinationId, $seckillId, $bargainId] = $event;

        // 订单数据创建之后的商品实际金额计算，佣金计算，优惠折扣计算，设置默认地址，清理购物车
        /** @var StoreOrderCreateServices $orderCreate */
        $orderCreate = app()->make(StoreOrderCreateServices::class);
        $orderCreate->orderCreateAfter($order, $group, $combinationId || $seckillId || $bargainId);

        // 清除订单缓存
        CacheService::delete('user_order_' . $uid . $key);

        // 写入订单记录表
        /** @var StoreOrderStatusServices $statusService */
        $statusService = app()->make(StoreOrderStatusServices::class);
        $statusService->save([
            'oid' => $order['id'],
            'change_type' => 'cache_key_create_order',
            'change_message' => '订单生成',
            'change_time' => time()
        ]);

        // 订单自动取消
        $this->pushJob($order['id'], $combinationId, $seckillId, $bargainId);

        // 下单记录
        ProductLogJob::dispatch(['order', ['uid' => $uid, 'order_id' => $order['id']]]);

        // 小票打印
        PrintJob::dispatch([$order['id'], 2]);
    }

    /**
     * 订单自动取消加入延迟消息队列
     * @param int $orderId
     * @param int $combinationId
     * @param int $seckillId
     * @param int $bargainId
     * @return mixed
     */
    public function pushJob(int $orderId, int $combinationId, int $seckillId, int $bargainId)
    {
        // 系统预设取消订单时间段
        $keyValue = ['order_cancel_time', 'order_activity_time', 'order_bargain_time', 'order_seckill_time', 'order_pink_time'];
        // 获取配置
        $systemValue = SystemConfigService::more($keyValue);
        // 格式化数据
        $systemValue = Arr::setValeTime($keyValue, is_array($systemValue) ? $systemValue : []);
        if ($combinationId) {
            $secs = $systemValue['order_pink_time'] ?: $systemValue['order_activity_time'];
        } elseif ($seckillId) {
            $secs = $systemValue['order_seckill_time'] ?: $systemValue['order_activity_time'];
        } elseif ($bargainId) {
            $secs = $systemValue['order_bargain_time'] ?: $systemValue['order_activity_time'];
        } else {
            $secs = $systemValue['order_cancel_time'];
        }
        // 未支付10分钟后发送短信
        UnpaidOrderSend::dispatchSecs(600, [$orderId]);
        // 未支付根据系统设置事件取消订单
        UnpaidOrderCancelJob::dispatchSecs((int)($secs * 3600), [$orderId]);
    }
}
```

#### 5.2.2 Trình xử lý sự kiện đăng ký người dùng

```php
<?php
namespace app\listener\user;

use app\jobs\AgentJob;
use app\services\activity\coupon\StoreCouponIssueServices;
use app\services\user\UserBillServices;
use app\services\user\UserServices;
use app\services\user\UserSpreadServices;
use crmeb\interfaces\ListenerInterface;

/**
 * 注册完成后置事件
 * Class RegisterListener
 * @package app\listener\user
 */
class RegisterListener implements ListenerInterface
{
    /**
     * 注册完成后置事件
     * @param $event
     * @throws \think\db\exception\DataNotFoundException
     * @throws \think\db\exception\DbException
     * @throws \think\db\exception\ModelNotFoundException
     */
    public function handle($event): void
    {
        [$spreadUid, $userType, $name, $uid, $isNew] = $event;

        if ($spreadUid) {
            if ($isNew) {
                // 邀请新用户增加经验
                /** @var UserBillServices $userBill */
                $userBill = app()->make(UserBillServices::class);
                $userBill->inviteUserIncExp((int)$spreadUid);
                // 增加推广佣金
                /** @var UserServices $userServices */
                $userServices = app()->make(UserServices::class);
                $userServices->addBrokeragePrice($uid, $spreadUid);

                // 推广新人 处理自己、上级分销等级升级
                AgentJob::dispatch([$uid]);
            }
            // 记录推广绑定关系
            /** @var UserSpreadServices $userSpreadServices */
            $userSpreadServices = app()->make(UserSpreadServices::class);
            $res = $userSpreadServices->setSpread($uid, $spreadUid);

            // 自定义消息-下级用户绑定成功
            if ($res) {
                $phone = app()->make(UserServices::class)->value($spreadUid, 'phone');
                event('CustomNoticeListener', [$spreadUid, ['nickname' => $name, 'time' => date('Y-m-d H:i:s'), 'phone' => $phone], 'spread_success']);
            }
        }

        if ($isNew) {
            // 新人优惠券发送
            /**@var StoreCouponIssueServices $storeCoupon */
            $storeCoupon = app()->make(StoreCouponIssueServices::class);
            $storeCoupon->userFirstSubGiveCoupon((int)$uid);

            // 人人分销开启推广权限
            if (sys_config('brokerage_func_status') && sys_config('store_brokerage_statu') == 2) {
                /** @var UserServices $userServices */
                $userServices = app()->make(UserServices::class);
                $userServices->update($uid, ['is_promoter' => 1]);
            }
        }
    }
}
```

## 6. Sự kiện tùy chỉnh

CRMEB hỗ trợ các sự kiện tùy chỉnh và đạt được khả năng mở rộng kinh doanh linh hoạt thông qua `CustomEventListener`:

### 6.1 Kích hoạt sự kiện tùy chỉnh

```php
// 触发自定义事件
event('CustomEventListener', ['event_mark', ['data1' => 'value1', 'data2' => 'value2']]);
```

### 6.2 Xử lý sự kiện tùy chỉnh

Các sự kiện tùy chỉnh được xử lý bởi `app\listener\CustomEventListener`, một trình nghe sẽ tìm nạp mã tùy chỉnh đã định cấu hình từ cơ sở dữ liệu và thực thi:

```php
<?php
namespace app\listener;

use app\services\system\SystemEventServices;
use think\facade\Log;

class CustomEventListener
{
    public function handle($event)
    {
        [$mark, $data] = $event;
        try {
            $list = app()->make(SystemEventServices::class)->selectList(['mark' => $mark, 'is_del' => 0, 'is_open' => 1])->toArray();
            foreach ($list as $item) {
                eval(json_decode($item['customCode']));
            }
        } catch (\Throwable $e) {
            $listener_log_open = config("log.listener_log", false);
            if ($listener_log_open) {
                $date = date('Y-m-d H:i:s', time());
                Log::write($date . '自定义事件错误:' . $e->getMessage(), 'listener');
            }
        }
    }
}
```

### 6.3 Cấu hình sự kiện tùy chỉnh

Các sự kiện tùy chỉnh có thể được định cấu hình thông qua hệ thống quản lý nền và các sự kiện tùy chỉnh có thể được thêm và quản lý trong "Cài đặt hệ thống" -> "Quản lý sự kiện".

## 7. Thực tiễn tốt nhất

### 7.1 Quy ước đặt tên sự kiện

- Tên sự kiện cần thể hiện rõ ý nghĩa và thời điểm diễn ra sự kiện. Ví dụ: `OrderCreateAfterListener` đại diện cho sự kiện sau khi đơn hàng được tạo.
- Sử dụng thuật ngữ CamelCase, viết hoa chữ cái đầu tiên

### 7.2 Nguyên tắc thiết kế trình nghe

- **Trách nhiệm duy nhất**: Mỗi người nghe chỉ chịu trách nhiệm xử lý một logic kinh doanh cụ thể
- **Không có tác dụng phụ**: Quá trình xử lý trình nghe không được sửa đổi dữ liệu sự kiện gốc để tránh ảnh hưởng đến các trình nghe khác
- **Xử lý ngoại lệ**: Nắm bắt các ngoại lệ trong trình nghe một cách thích hợp để tránh lỗi của một trình nghe duy nhất ảnh hưởng đến toàn bộ quá trình xử lý sự kiện

### 7.3 Tối ưu hóa hiệu suất

- **Xử lý không đồng bộ**: Đối với các hoạt động tốn thời gian, nên sử dụng hàng đợi để xử lý không đồng bộ, chẳng hạn như gửi tin nhắn văn bản, tạo báo cáo, v.v.
- **Sử dụng bộ đệm**: Sử dụng bộ đệm hợp lý để giảm truy vấn cơ sở dữ liệu và nâng cao hiệu quả xử lý
- **Tránh phụ thuộc vòng tròn**: Người nghe không nên phụ thuộc vào nhau để tránh hình thành các cuộc gọi vòng tròn.

## 8. Câu hỏi và giải pháp thường gặp

### 8.1 Sự kiện không được kích hoạt

**Sự cố**: Trình nghe không được thực thi sau khi gọi hàm `event()`.

**Giải pháp**:
- Kiểm tra xem tên sự kiện có khớp với tên đã đăng ký trong `event.php` không
- Kiểm tra xem lớp người nghe có triển khai đúng giao diện `ListenerInterface` không
- Kiểm tra xem lớp người nghe có được đăng ký chính xác với sự kiện tương ứng hay không

### 8.2 Trình tự thực thi của trình nghe

**Câu hỏi**: Cần kiểm soát thứ tự thực hiện của người nghe.

**Giải pháp**:
- Trong `event.php` thứ tự đăng ký của người nghe xác định thứ tự thực hiện
- Để điều khiển phức tạp hơn, bạn có thể kích hoạt các sự kiện khác trong trình nghe theo cách thủ công

### 8.3 Truyền dữ liệu sự kiện

**Sự cố**: Trình nghe không thể lấy được dữ liệu sự kiện hoàn chỉnh.

**Giải pháp**:
- Đảm bảo rằng tất cả dữ liệu cần thiết được truyền khi sự kiện được kích hoạt
- Sử dụng dạng mảng để truyền dữ liệu dễ dàng mở rộng và bảo trì
- Xác nhận hợp lệ và chuyển đổi dữ liệu trong trình nghe

## 9. Gợi ý tối ưu hóa code

### 9.1 Tối ưu hóa xử lý ngoại lệ của trình nghe

**Vấn đề**: Một số trình nghe có thể thiếu cơ chế xử lý ngoại lệ hoàn chỉnh, khiến cho một trình nghe bị lỗi và ảnh hưởng đến toàn bộ quá trình xử lý sự kiện.

**Đề xuất**: Thêm khối try-catch trong phương thức `handle()` của trình nghe để nắm bắt và ghi lại các ngoại lệ nhằm đảm bảo rằng ngay cả khi trình nghe không thành công, điều đó sẽ không ảnh hưởng đến việc thực thi của các trình nghe khác.

```php
public function handle($event): void
{
    try {
        // 监听器逻辑
    } catch (\Exception $e) {
        // 记录异常日志
        Log::error('Listener error: ' . $e->getMessage(), [
            'listener' => __CLASS__,
            'event' => $event,
            'trace' => $e->getTraceAsString()
        ]);
        // 可以根据需要添加其他处理逻辑
    }
}
```

### 9.2 Tối ưu hóa xác thực dữ liệu sự kiện

**Vấn đề**: Trình nghe chủ yếu dựa vào dữ liệu sự kiện nhưng thiếu xác minh tính hợp lệ của dữ liệu, điều này có thể dẫn đến lỗi thời gian chạy.

**Đề xuất**: Thêm logic xác thực dữ liệu trong trình nghe để đảm bảo rằng dữ liệu nhận được đáp ứng định dạng và yêu cầu mong đợi.

```php
public function handle($event): void
{
    // 验证事件数据
    if (!is_array($event) || count($event) < 4) {
        Log::warning('Invalid event data', [
            'listener' => __CLASS__,
            'event' => $event
        ]);
        return;
    }
    
    [$order, $group, $uid, $key] = $event;
    
    // 验证必要参数
    if (empty($order['id']) || empty($uid)) {
        Log::warning('Missing required parameters', [
            'listener' => __CLASS__,
            'order_id' => $order['id'] ?? null,
            'uid' => $uid
        ]);
        return;
    }
    
    // 监听器逻辑
}
```

### 9.3 Tối ưu hóa điểm kích hoạt sự kiện

**Vấn đề**: Các điểm kích hoạt sự kiện có thể quá rải rác, khiến việc theo dõi vị trí và thời gian diễn ra sự kiện trở nên khó khăn.

**Đề xuất**: Thiết lập tài liệu hoặc thông số kỹ thuật chú thích cho các điểm kích hoạt sự kiện và ghi lại rõ ràng vị trí kích hoạt, thời gian và cấu trúc dữ liệu được truyền của từng sự kiện để tạo điều kiện thuận lợi cho việc bảo trì và mở rộng sau này.

```php
/**
 * 创建订单
 * @param array $data 订单数据
 * @return array 订单信息
 * @event OrderCreateAfterListener 订单创建后触发，传递参数：[$order, $group, $uid, $key, $combinationId, $seckillId, $bargainId]
 */
public function createOrder(array $data)
{
    // 订单创建逻辑
    
    // 触发事件
    event('OrderCreateAfterListener', [$order, $group, $uid, $key, $combinationId, $seckillId, $bargainId]);
    
    return $order;
}
```

## 10. Ví dụ đầu vào và đầu ra

### 10.1 Kích hoạt sự kiện tạo lệnh

**đi vào**:
```php
// 订单创建完成后触发事件
$order = [
    'id' => 1001,
```

##11. Tóm tắt

Hệ thống sự kiện của CRMEB cung cấp cơ chế giao tiếp giữa các mô-đun linh hoạt, tách rời và thực hiện việc tách biệt và mở rộng logic kinh doanh thông qua sự hợp tác của các sự kiện và người nghe.Việc sử dụng đúng hệ thống sự kiện có thể:

1. **Cải thiện khả năng bảo trì của mã**: Tập trung logic kinh doanh có liên quan vào trình nghe để hỗ trợ quản lý và bảo trì
2. **Nâng cao khả năng mở rộng của hệ thống**: Thông qua cơ chế sự kiện, logic nghiệp vụ mới có thể được thêm dễ dàng mà không cần sửa đổi mã gốc.
3. **Giảm sự ghép nối giữa các mô-đun**: Các mô-đun giao tiếp thông qua các sự kiện thay vì phụ thuộc trực tiếp, làm giảm sự ghép nối giữa các mô-đun
4. **Cải thiện tốc độ phản hồi của hệ thống**: Đối với các hoạt động tốn thời gian, việc xử lý không đồng bộ có thể được thực hiện thông qua hàng đợi để cải thiện tốc độ phản hồi của hệ thống.

Trong quá trình phát triển, cần tuân thủ các quy ước đặt tên sự kiện, nguyên tắc thiết kế trình nghe và đề xuất tối ưu hóa hiệu suất để đảm bảo hệ thống sự kiện hoạt động hiệu quả.Bằng cách sử dụng hợp lý cơ chế sự kiện, chất lượng mã và hiệu quả phát triển có thể được cải thiện đáng kể, tạo nền tảng tốt cho việc bảo trì và mở rộng hệ thống lâu dài.
