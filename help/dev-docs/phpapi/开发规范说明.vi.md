# Thông số kỹ thuật phát triển

## 🎯 Gia hạn dựa trên thông số kỹ thuật hiện có

### 1. Cách đặt tên và thông số sử dụng lớp dịch vụ
```php
// ✅ 正确示例
class UserServices extends BaseServices {
    public function getUserInfo(int $uid) {}
    public function updateUserStatus(int $uid, int $status) {}
}

// ❌ 避免在Controller中直接操作数据库
// 不要这样写：Db::name('user')->where('id', $uid)->update($data)
```

### 2. Phân chia trách nhiệm ở lớp DAO
```php
// ✅ DAO只负责基础CRUD
class UserDao extends BaseDao {
    public function getById(int $id) {}
    public function updateById(int $id, array $data) {}
}

// Service调用DAO
class UserServices {
    public function complexBusiness() {
        $user = $this->dao->getById($id);
        // 业务逻辑处理
        $this->dao->updateById($id, $data);
    }
}
```

### 3. Tiêu chuẩn xử lý ngoại lệ
```php
// 使用项目特定异常类
throw new ApiException('错误信息', 400);
throw new AdminException('管理端错误', 500);

// 统一返回格式
return $this->success($data);
return $this->fail('错误信息');
```

### 4. Vị trí xác minh thông số
```php
// 验证放在validate目录下对应文件
// adminapi/validate/user/UserValidata.php
class UserValidata extends Validate {
    protected $rule = [
        'nickname' => 'require|max:25',
        'phone' => 'require|mobile'
    ];
}
```

###5. Chú thích bổ sung chuẩn
```php
/**
 * 获取用户信息（包含扩展信息）
 * @param int $uid 用户ID
 * @param array $with 关联查询 ['order', 'address']
 * @return array
 * @throws ApiException
 */
public function getUserDetail(int $uid, array $with = []) {
    // 业务逻辑
}
```

## 🔧 Thông số sử dụng công cụ
- Sử dụng các lớp công cụ trong `crmeb\utils\`
- Cấu hình được sử dụng `SystemConfigService`
- Hoạt động bộ đệm sử dụng `CacheService`
- Tải tệp lên bằng `UploadService`

## 📝 Thông số kỹ thuật gửi mã
1. Chạy thử nghiệm trước khi cam kết
2. Định dạng thông tin gửi bài: `[类型] 描述`
   - `[feat] 新增用户积分功能`
   - `[fix] 修复订单状态更新问题`
   - `[docs] 更新API文档`
   - `[style] 调整代码格式`
3. Tránh các cam kết rườm rà, mỗi cam kết tập trung vào một tính năng hoặc sửa lỗi

## 🚧 Quản lý chi nhánh
- `master` - mã môi trường sản xuất
- `develop` - nhánh phát triển
- `feature/xxx` - nhánh phát triển tính năng
- `hotfix/xxx` - chi nhánh sửa chữa khẩn cấp

## 🧪 Thông số kiểm tra
1. Kiểm tra đơn vị bao gồm logic kinh doanh cốt lõi
2. Kiểm thử tích hợp bao gồm giao diện API
3. Dữ liệu thử nghiệm được tạo bằng chế độ xuất xưởng
4. Đặt tên trường hợp thử nghiệm: `testMethodNameWhenConditionThenResult`
