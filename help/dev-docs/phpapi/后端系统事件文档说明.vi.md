# Mô tả tài liệu sự kiện hệ thống phụ trợ CRMEB

## 1. Tổng quan về cơ chế sự kiện

Hệ thống phụ trợ CRMEB áp dụng kiến ​​trúc hướng sự kiện để đạt được khả năng tách rời và liên lạc giữa các mô-đun thông qua cơ chế sự kiện.Hệ thống sự kiện cho phép tương tác giữa các mô-đun khác nhau và mở rộng logic nghiệp vụ mà không phụ thuộc trực tiếp.

### 1.1 Khái niệm cốt lõi

- **Sự kiện**: Các hành động hoặc thay đổi trạng thái cụ thể xảy ra trong hệ thống, chẳng hạn như tạo đơn hàng, đăng ký người dùng, v.v.
- **Listener**: Lớp lắng nghe các sự kiện cụ thể và thực thi logic xử lý tương ứng.
- **Trình kích hoạt sự kiện (Trình kích hoạt)**: Gọi một sự kiện tại một điểm logic nghiệp vụ cụ thể để thông báo cho người nghe có liên quan thực hiện.

## 2. Định nghĩa giao diện Listener

Tất cả trình nghe phải triển khai giao diện `crmeb\interfaces\ListenerInterface`, giao diện này xác định phương pháp xử lý sự kiện thống nhất.

```php
<?php
namespace crmeb\interfaces;

interface ListenerInterface
{
    public function handle($event): void;
}
```

### 2.1 Mô tả giao diện

- **phương thức xử lý**: Phương thức cốt lõi của việc xử lý sự kiện, nhận thông số `$event`, chứa dữ liệu được truyền khi sự kiện được kích hoạt.
- Kiểu trả về: `void`, không cần giá trị trả về sau khi quá trình xử lý trình nghe hoàn tất.

## 3. Định nghĩa và đăng ký sự kiện

Các sự kiện được xác định và đăng ký thông qua tệp `app/event.php`, tệp này trả về một mảng chứa cấu hình sự kiện.

### 3.1 Cấu trúc cấu hình sự kiện

```php
return [
    'bind' => [], // 事件绑定
    'listen' => [ // 事件监听
        'EventName' => [
            'Listener1::class',
            'Listener2::class',
        ],
    ],
];
```

### 3.2 Ví dụ đăng ký sự kiện

```php
return [
    'listen' => [
        'OrderCreateAfterListener' => [\app\listener\order\OrderCreateAfterListener::class], // 订单创建后置事件
        'UserRegisterListener' => [\app\listener\user\RegisterListener::class], // 用户注册后置事件
        // 更多事件...
    ],
];
```

## 5. Phương thức kích hoạt sự kiện

Các sự kiện được kích hoạt thông qua hàm `event()`, đây là một hàm toàn cục do khung ThinkPHP cung cấp.

### 5.1 Phương pháp kích hoạt cơ bản

```php
// 触发事件
 event('EventName', $eventData);

// 示例：触发订单创建事件
 event('OrderCreateAfterListener', [$order, $group, $uid, $key]);
```

### 5.2 Truyền dữ liệu sự kiện

Khi sự kiện được kích hoạt, bất kỳ loại dữ liệu nào cũng có thể được truyền và trình nghe sẽ nhận được dữ liệu đó thông qua tham số `$event`.Dữ liệu thường được truyền dưới dạng mảng, chứa tất cả thông tin cần thiết để xử lý logic nghiệp vụ.

## 6. Sự kiện tùy chỉnh

Ngoài các sự kiện tích hợp của hệ thống, CRMEB còn hỗ trợ các sự kiện tùy chỉnh để đạt được khả năng mở rộng kinh doanh linh hoạt thông qua `CustomEventListener`.

### 6.1 Kích hoạt sự kiện tùy chỉnh

```php
// 触发自定义事件
 event('CustomEventListener', ['event_mark', ['data1' => 'value1', 'data2' => 'value2']]);
```

### 6.2 Xử lý sự kiện tùy chỉnh

Các sự kiện tùy chỉnh được xử lý bởi `app\listener\CustomEventListener`, một trình nghe sẽ tìm nạp mã tùy chỉnh đã định cấu hình từ cơ sở dữ liệu và thực thi mã đó.

```php
<?php
namespace app\listener;

use app\services\system\SystemEventServices;
use think\facade\Log;

class CustomEventListener
{
    public function handle($event)
    {
        [$mark, $data] = $event;
        try {
            $list = app()->make(SystemEventServices::class)->selectList(['mark' => $mark, 'is_del' => 0, 'is_open' => 1])->toArray();
            foreach ($list as $item) {
                eval(json_decode($item['customCode']));
            }
        } catch (\Throwable $e) {
            $listener_log_open = config("log.listener_log", false);
            if ($listener_log_open) {
                $date = date('Y-m-d H:i:s', time());
                Log::write($date . '自定义事件错误:' . $e->getMessage(), 'listener');
            }
        }
    }
}
```

##7. Quy trình xử lý sự kiện

1. **Kích hoạt sự kiện**: Kích hoạt các sự kiện cụ thể thông qua hàm `event()` trong logic nghiệp vụ.
2. **Phân phối sự kiện**: Hệ thống tìm kiếm danh sách người nghe tương ứng dựa trên tên sự kiện.
3. **Thực thi trình nghe**: Gọi lần lượt phương thức `handle()` của từng trình nghe và truyền dữ liệu sự kiện.
4. **Xử lý nghiệp vụ**: Người nghe thực hiện logic nghiệp vụ tương ứng của họ, chẳng hạn như xử lý dữ liệu, gửi tin nhắn, v.v.
5. **Xử lý hoàn tất**: Sau khi tất cả các trình nghe được thực thi, quá trình xử lý sự kiện sẽ kết thúc.

## 8. Ví dụ triển khai Listener

### 8.1 Trình xử lý sự kiện tạo đơn hàng

```php
<?php
namespace app\listener\order;

use app\jobs\notice\PrintJob;
use app\jobs\OrderCreateAfterJob;
use app\jobs\OrderJob;
use app\jobs\ProductLogJob;
use app\jobs\UnpaidOrderCancelJob;
use app\jobs\UnpaidOrderSend;
use app\services\order\StoreOrderCreateServices;
use app\services\order\StoreOrderStatusServices;
use crmeb\interfaces\ListenerInterface;
use crmeb\services\CacheService;
use crmeb\services\SystemConfigService;
use crmeb\utils\Arr;

/**
 * 订单创建后置事件
 * Class OrderCreateAfterListener
 * @package app\listener\order
 */
class OrderCreateAfterListener implements ListenerInterface
{
    public function handle($event): void
    {
        [$order, $group, $uid, $key, $combinationId, $seckillId, $bargainId] = $event;

        // 订单数据创建之后的商品实际金额计算，佣金计算，优惠折扣计算，设置默认地址，清理购物车
        /** @var StoreOrderCreateServices $orderCreate */
        $orderCreate = app()->make(StoreOrderCreateServices::class);
        $orderCreate->orderCreateAfter($order, $group, $combinationId || $seckillId || $bargainId);

        // 清除订单缓存
        CacheService::delete('user_order_' . $uid . $key);

        // 写入订单记录表
        /** @var StoreOrderStatusServices $statusService */
        $statusService = app()->make(StoreOrderStatusServices::class);
        $statusService->save([
            'oid' => $order['id'],
            'change_type' => 'cache_key_create_order',
            'change_message' => '订单生成',
            'change_time' => time()
        ]);

        // 订单自动取消
        $this->pushJob($order['id'], $combinationId, $seckillId, $bargainId);

        // 下单记录
        ProductLogJob::dispatch(['order', ['uid' => $uid, 'order_id' => $order['id']]]);

        // 小票打印
        PrintJob::dispatch([$order['id'], 2]);
    }

    /**
     * 订单自动取消加入延迟消息队列
     * @param int $orderId
     * @param int $combinationId
     * @param int $seckillId
     * @param int $bargainId
     * @return mixed
     */
    public function pushJob(int $orderId, int $combinationId, int $seckillId, int $bargainId)
    {
        // 系统预设取消订单时间段
        $keyValue = ['order_cancel_time', 'order_activity_time', 'order_bargain_time', 'order_seckill_time', 'order_pink_time'];
        // 获取配置
        $systemValue = SystemConfigService::more($keyValue);
        // 格式化数据
        $systemValue = Arr::setValeTime($keyValue, is_array($systemValue) ? $systemValue : []);
        if ($combinationId) {
            $secs = $systemValue['order_pink_time'] ?: $systemValue['order_activity_time'];
        } elseif ($seckillId) {
            $secs = $systemValue['order_seckill_time'] ?: $systemValue['order_activity_time'];
        } elseif ($bargainId) {
            $secs = $systemValue['order_bargain_time'] ?: $systemValue['order_activity_time'];
        } else {
            $secs = $systemValue['order_cancel_time'];
        }
        // 未支付10分钟后发送短信
        UnpaidOrderSend::dispatchSecs(600, [$orderId]);
        // 未支付根据系统设置事件取消订单
        UnpaidOrderCancelJob::dispatchSecs((int)($secs * 3600), [$orderId]);
    }
}
```

### 8.2 Trình xử lý sự kiện đăng ký người dùng

```php
<?php
namespace app\listener\user;

use app\jobs\AgentJob;
use app\services\activity\coupon\StoreCouponIssueServices;
use app\services\user\UserBillServices;
use app\services\user\UserServices;
use app\services\user\UserSpreadServices;
use crmeb\interfaces\ListenerInterface;

/**
 * 注册完成后置事件
 * Class RegisterListener
 * @package app\listener\user
 */
class RegisterListener implements ListenerInterface
{
    /**
     * 注册完成后置事件
     * @param $event
     * @throws \think\db\exception\DataNotFoundException
     * @throws \think\db\exception\DbException
     * @throws \think\db\exception\ModelNotFoundException
     */
    public function handle($event): void
    {
        [$spreadUid, $userType, $name, $uid, $isNew] = $event;

        if ($spreadUid) {
            if ($isNew) {
                // 邀请新用户增加经验
                /** @var UserBillServices $userBill */
                $userBill = app()->make(UserBillServices::class);
                $userBill->inviteUserIncExp((int)$spreadUid);
                // 增加推广佣金
                /** @var UserServices $userServices */
                $userServices = app()->make(UserServices::class);
                $userServices->addBrokeragePrice($uid, $spreadUid);

                // 推广新人 处理自己、上级分销等级升级
                AgentJob::dispatch([$uid]);
            }
            // 记录推广绑定关系
            /** @var UserSpreadServices $userSpreadServices */
            $userSpreadServices = app()->make(UserSpreadServices::class);
            $res = $userSpreadServices->setSpread($uid, $spreadUid);

            // 自定义消息-下级用户绑定成功
            if ($res) {
                $phone = app()->make(UserServices::class)->value($spreadUid, 'phone');
                event('CustomNoticeListener', [$spreadUid, ['nickname' => $name, 'time' => date('Y-m-d H:i:s'), 'phone' => $phone], 'spread_success']);
            }
        }

        if ($isNew) {
            // 新人优惠券发送
            /**@var StoreCouponIssueServices $storeCoupon */
            $storeCoupon = app()->make(StoreCouponIssueServices::class);
            $storeCoupon->userFirstSubGiveCoupon((int)$uid);

            // 人人分销开启推广权限
            if (sys_config('brokerage_func_status') && sys_config('store_brokerage_statu') == 2) {
                /** @var UserServices $userServices */
                $userServices = app()->make(UserServices::class);
                $userServices->update($uid, ['is_promoter' => 1]);
            }
        }
    }
}
```

## 9. Các phương pháp hay nhất

### 9.1 Quy ước đặt tên sự kiện

- Tên sự kiện cần thể hiện rõ ý nghĩa và thời điểm diễn ra sự kiện. Ví dụ: `OrderCreateAfterListener` đại diện cho sự kiện sau khi đơn hàng được tạo.
- Sử dụng ký hiệu CamelCase, viết hoa chữ cái đầu tiên.

### 9.2 Nguyên tắc thiết kế trình nghe

- **Trách nhiệm duy nhất**: Mỗi người nghe chỉ chịu trách nhiệm xử lý một logic kinh doanh cụ thể.
- **Không có tác dụng phụ**: Quá trình xử lý trình nghe không được sửa đổi dữ liệu sự kiện gốc để tránh ảnh hưởng đến các trình nghe khác.
- **Xử lý ngoại lệ**: Nắm bắt các ngoại lệ trong trình nghe một cách thích hợp để tránh lỗi của một trình nghe duy nhất ảnh hưởng đến toàn bộ quá trình xử lý sự kiện.

### 9.3 Tối ưu hóa hiệu suất

- **Xử lý không đồng bộ**: Đối với các hoạt động tốn thời gian, nên sử dụng hàng đợi để xử lý không đồng bộ, chẳng hạn như gửi tin nhắn văn bản, tạo báo cáo, v.v.
- **Sử dụng bộ đệm**: Sử dụng bộ đệm đúng cách để giảm truy vấn cơ sở dữ liệu và cải thiện hiệu quả xử lý.
- **Tránh phụ thuộc vòng tròn**: Người nghe không nên phụ thuộc vào nhau để tránh gọi vòng tròn.

##10. Câu hỏi và giải pháp thường gặp

### 10.1 Sự kiện không được kích hoạt

**Sự cố**: Trình nghe không được thực thi sau khi gọi hàm `event()`.

**Giải pháp**:
- Kiểm tra xem tên sự kiện có khớp với tên đã đăng ký trong `event.php` hay không.
- Kiểm tra xem lớp người nghe có triển khai đúng giao diện `ListenerInterface` hay không.
- Kiểm tra xem lớp người nghe có được đăng ký chính xác với sự kiện tương ứng hay không.

### 10.2 Trình tự thực thi trình nghe

**Câu hỏi**: Cần kiểm soát thứ tự thực hiện của người nghe.

**Giải pháp**:
- Trong `event.php`, thứ tự đăng ký trình nghe sẽ xác định thứ tự thực hiện.
- Để điều khiển phức tạp hơn, bạn có thể kích hoạt các sự kiện khác trong trình nghe theo cách thủ công.

### 10.3 Truyền dữ liệu sự kiện

**Sự cố**: Trình nghe không thể lấy được dữ liệu sự kiện hoàn chỉnh.

**Giải pháp**:
- Đảm bảo tất cả dữ liệu cần thiết được truyền khi sự kiện diễn ra.
- Sử dụng dạng mảng để truyền dữ liệu dễ dàng mở rộng và bảo trì.
- Xác nhận hợp lệ và chuyển đổi dữ liệu trong trình nghe.

##11. Tóm tắt

Hệ thống sự kiện của CRMEB cung cấp cơ chế giao tiếp giữa các mô-đun linh hoạt, tách rời và thực hiện việc tách biệt và mở rộng logic kinh doanh thông qua sự hợp tác của các sự kiện và người nghe.Việc sử dụng hợp lý hệ thống sự kiện có thể cải thiện khả năng bảo trì và khả năng mở rộng của mã, đồng thời giảm sự ghép nối giữa các mô-đun.

Trong quá trình phát triển, cần tuân thủ các quy ước đặt tên sự kiện, nguyên tắc thiết kế trình nghe và đề xuất tối ưu hóa hiệu suất để đảm bảo hệ thống sự kiện hoạt động hiệu quả.
