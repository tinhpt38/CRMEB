# Tài liệu phát triển tác vụ hàng đợi hệ thống

## 1. Tổng quan về cơ chế xếp hàng

Hệ thống CRMEB sử dụng cơ chế tác vụ xếp hàng dựa trên Hàng đợi ThinkPHP để xử lý các hoạt động tiêu tốn thời gian và cải thiện tốc độ phản hồi của hệ thống cũng như khả năng xử lý đồng thời.Các tác vụ xếp hàng hỗ trợ thực thi không đồng bộ, thực thi bị trì hoãn, thử lại lỗi và các chức năng khác, đồng thời phù hợp để xử lý đơn hàng, đẩy tin nhắn, phân tích dữ liệu và các tình huống khác.

### 1.1 Thành phần cốt lõi

- **Giao diện tác vụ**: `JobInterface` - xác định giao diện chuẩn để thực thi tác vụ
- **Lớp cơ sở nhiệm vụ**: `BaseJobs` - Cung cấp cách triển khai cơ bản về thực thi nhiệm vụ
- **Công cụ xếp hàng**: `Queue` - Cung cấp chức năng tạo và quản lý các tác vụ hàng đợi
- **Tính năng xếp hàng**: `QueueTrait` - Cung cấp phương pháp lập lịch xếp hàng nhanh
- **Tệp cấu hình**: `queue.php` - Định cấu hình các tham số và trình điều khiển hàng đợi

## 2. Cấu hình hàng đợi

### 2.1 Tệp cấu hình

Tệp cấu hình hàng đợi được đặt tại `/crmeb/config/queue.php`. Các mục cấu hình chính bao gồm:

```php
return [
    // 默认队列驱动
    'default'     => 'redis',
    
    // 队列连接方式配置
    'connections' => [
        'sync'     => [
            'type' => 'sync',
        ],
        'database' => [
            'type'       => 'database',
            'queue'      => 'default',
            'table'      => 'jobs',
            'connection' => null,
        ],
        'redis'    => [
            'type'       => 'redis',
            'queue'      => 'default',
            'host'       => env('redis.host', '127.0.0.1'),
            'port'       => env('redis.port', 6379),
            'password'   => env('redis.password', ''),
            'select'     => env('redis.select', 0),
            'timeout'    => 0,
            'persistent' => false,
        ],
    ],
    
    // 失败队列配置
    'failed'      => [
        'type'  => 'none',
        'table' => 'failed_jobs',
    ],
];
```

### 2.2 Hướng dẫn cấu hình

- **default**: Trình điều khiển hàng đợi mặc định, hỗ trợ đồng bộ (synchronization), cơ sở dữ liệu (database), redis (Redis)
- **kết nối**: Cấu hình kết nối hàng đợi, có thể cấu hình nhiều trình điều khiển hàng đợi
- **failed**: Cấu hình hàng đợi bị lỗi, dùng để lưu trữ các tác vụ bị lỗi

## 3. Định nghĩa giao diện tác vụ

### 3.1 Giao diện công việc

Giao diện tác vụ xác định phương thức thực thi tiêu chuẩn của các tác vụ hàng đợi:

```php
namespace crmeb\interfaces;

use think\queue\Job;

interface JobInterface
{
    public function fire(Job $job, $data): void;
}
```

- **fire**: Phương thức nhập để thực thi tác vụ, nhận đối tượng Công việc và dữ liệu tác vụ

## 4. Lớp cơ sở nhiệm vụ

### 4.1 Công việc cơ bản

Lớp cơ sở tác vụ triển khai giao diện `JobInterface` và cung cấp logic cơ bản để thực thi tác vụ:

```php
namespace crmeb\basic;

use crmeb\interfaces\JobInterface;
use think\queue\Job;
use think\facade\Log;

abstract class BaseJobs implements JobInterface
{
    /**
     * @param Job $job
     * @param $data
     */
    public function fire(Job $job, $data): void
    {
        try {
            $method = $data['method'] ?? 'doJob';
            if (method_exists($this, $method)) {
                if (!isset($data['data'])) {
                    $res = $this->{$method}();
                } else {
                    $res = $this->{$method}(...$data['data']);
                }
                if ($res) {
                    $job->delete();
                } else {
                    if ($job->attempts() > 3) {
                        $job->delete();
                    } else {
                        $job->release();
                    }
                }
            } else {
                $job->delete();
            }
        } catch (\Throwable $e) {
            Log::error('队列任务执行失败：' . $e->getMessage());
            if ($job->attempts() > 3) {
                $job->delete();
            } else {
                $job->release();
            }
        }
    }
}
```

- **fire**: Phương thức triển khai giao diện JobInterface để xử lý việc thực thi tác vụ, bắt lỗi và thử lại lỗi
- **doJob**: Phương thức thực thi tác vụ mặc định, các lớp con có thể ghi đè

## 5. Lớp công cụ xếp hàng

### Hàng đợi 5.1

Lớp công cụ hàng đợi cung cấp một phương thức gọi chuỗi để tạo và quản lý các tác vụ hàng đợi:

```php
namespace crmeb\utils;

use think\facade\Config;
use think\facade\Queue as QueueThink;
use think\facade\Log;

class Queue
{
    // 任务执行方法
    protected $do = 'doJob';
    
    // 任务类名
    protected $job;
    
    // 错误次数
    protected $errorCount = 3;
    
    // 数据
    protected $data;
    
    // 队列名
    protected $queueName = null;
    
    // 延迟执行秒数
    protected $secs = 0;
    
    // ... 其他方法
}
```

### 5.2 Đặc điểm hàng đợi

Tính năng xếp hàng cung cấp phương pháp lập lịch xếp hàng nhanh:

```php
namespace crmeb\traits;

trait QueueTrait
{
    /**
     * 加入队列
     * @param string $queueName
     * @param array $data
     * @return bool
     */
    public static function dispatch(string $queueName = null, ...$data)
    {
        $class = get_called_class();
        return Queue::instance()->job($class)->data($data)->queue($queueName)->push();
    }
    
    /**
     * 延迟加入队列
     * @param int $secs
     * @param string|null $queueName
     * @param array $data
     * @return bool
     */
    public static function dispatchSecs(int $secs, string $queueName = null, ...$data)
    {
        $class = get_called_class();
        return Queue::instance()->job($class)->data($data)->secs($secs)->queue($queueName)->push();
    }
}
```

## 6. Tạo tác vụ xếp hàng

### 6.1 Các bước tạo tác vụ

1. Tạo một lớp nhiệm vụ và kế thừa `BaseJobs`
2. Triển khai phương thức `doJob` hoặc phương thức tùy chỉnh
3. Sử dụng phương thức phím tắt do `QueueTrait` cung cấp để lên lịch tác vụ

### 6.2 Ví dụ về nhiệm vụ

```php
namespace app\jobs;

use crmeb\basic\BaseJobs;
use crmeb\traits\QueueTrait;
use think\facade\Log;

class OrderCreateAfterJob extends BaseJobs
{
    use QueueTrait;
    
    /**
     * 订单后置处理
     * @param $orderInfo
     * @param $data
     * @param $activity
     * @return bool
     */
    public function doJob($orderInfo, $data, $activity)
    {
        try {
            // 处理订单逻辑
            // ...
            
            return true;
        } catch (\Throwable $e) {
            Log::error('订单后置处理失败：' . $e->getMessage());
            return false;
        }
    }
}
```

## 7. Lên lịch các tác vụ xếp hàng

### 7.1 Lập kế hoạch cơ bản

Lên lịch tác vụ bằng phương pháp `dispatch` do `QueueTrait` cung cấp:

```php
// 调度订单后置处理任务
OrderCreateAfterJob::dispatch(null, $orderInfo, $data, $activity);
```

### 7.2 Trì hoãn lịch trình

Sử dụng phương pháp `dispatchSecs` do `QueueTrait` cung cấp để trì hoãn các tác vụ lên lịch:

```php
// 延迟10秒执行订单后置处理任务
OrderCreateAfterJob::dispatchSecs(10, null, $orderInfo, $data, $activity);
```

### 7.3 Lập lịch sử dụng công cụ Queue

Sử dụng lớp tiện ích `Queue` để lên lịch linh hoạt hơn:

```php
use crmeb\utils\Queue;

// 创建并调度任务
Queue::instance()
    ->job(OrderCreateAfterJob::class)
    ->data($orderInfo, $data, $activity)
    ->secs(10)
    ->queue('order')
    ->push();
```

##8. Quá trình thực hiện nhiệm vụ

1. **Lập lịch tác vụ**: Thêm tác vụ vào hàng đợi thông qua các công cụ `dispatch` hoặc `Queue`
2. **Tiêu thụ tác vụ**: Quá trình tiêu thụ hàng đợi nhận các nhiệm vụ từ hàng đợi
3. **Thực thi tác vụ**: Gọi phương thức `fire` của lớp tác vụ để thực thi tác vụ
4. **Xử lý kết quả**:
- Thực hiện thành công: xóa tác vụ
- Lỗi thực thi: quyết định có thực hiện lại hay không dựa trên số lần thử lại
- Vượt quá giới hạn thử lại: chuyển tác vụ sang hàng đợi lỗi (nếu được định cấu hình)

##9. Quản lý hàng đợi

### 9.1 Bắt đầu xếp hàng người tiêu dùng

Bắt đầu sử dụng hàng đợi bằng các công cụ dòng lệnh của ThinkPHP:

```bash
# 启动默认队列的消费者
php think queue:listen

# 启动指定队列的消费者
php think queue:listen --queue order

# 启动守护进程模式的消费者
php think queue:work --daemon
```

### 9.2 Xem trạng thái hàng đợi

```bash
# 查看队列任务数
php think queue:status

# 查看失败任务
php think queue:failed

# 重试失败任务
php think queue:retry all

# 删除失败任务
php think queue:flush
```

## 10. Các phương pháp hay nhất

### 10.1 Nguyên tắc thiết kế nhiệm vụ

- **Trách nhiệm duy nhất**: Mỗi công việc chỉ chịu trách nhiệm cho một chức năng
- **Bất lực**: Thực hiện nhiệm vụ nhiều lần sẽ không gây tác dụng phụ
- **Tính toàn vẹn dữ liệu**: Đảm bảo tính toàn vẹn của dữ liệu cần thiết để thực thi tác vụ
- **Xử lý lỗi**: Xử lý đúng các trường hợp ngoại lệ trong quá trình thực thi tác vụ

### 10.2 Tối ưu hóa hiệu suất

- Đặt số lần thử lại không thành công hợp lý để tránh số lần thử lại vô số lần
- Chia nhỏ các tác vụ tốn thời gian để nâng cao khả năng xử lý đồng thời
- Sử dụng trình điều khiển hàng đợi phù hợp, Redis phù hợp với các kịch bản có tính tương tranh cao
- Thường xuyên xóa hàng đợi lỗi để tránh tích lũy dữ liệu

### 10.3 Giám sát và ghi nhật ký

- Ghi lại nhật ký thực hiện nhiệm vụ để hỗ trợ khắc phục sự cố
- Theo dõi độ dài hàng đợi và phát hiện kịp thời các tắc nghẽn trong quá trình xử lý
-Đặt cơ chế cảnh báo để thông báo kịp thời cho bạn khi tích lũy nhiệm vụ xếp hàng

## 11. Câu hỏi thường gặp

### 11.1 Thực hiện tác vụ không thành công

- Kiểm tra xem dữ liệu nhiệm vụ đã hoàn thành chưa
- Kiểm tra xem các dịch vụ mà nhiệm vụ phụ thuộc vào có sẵn không
- Kiểm tra file log để xác định nguyên nhân lỗi
- Kiểm tra xem trình điều khiển hàng đợi có hoạt động tốt không

### 11.2 Tích lũy tác vụ hàng đợi

- Tăng số lượng quy trình tiêu dùng hàng đợi
- Tối ưu hóa logic thực hiện nhiệm vụ và giảm thời gian thực hiện
- Kiểm tra tắc nghẽn hiệu suất trình điều khiển hàng đợi
- Cân nhắc sử dụng trình điều khiển hàng đợi hiệu quả hơn

### 11.3 Tác vụ bị trì hoãn không được thực thi

- Kiểm tra xem người tiêu dùng hàng đợi có chạy đúng không
- Kiểm tra xem cài đặt thời gian trễ có đúng không
- Kiểm tra xem trình điều khiển hàng đợi có hỗ trợ các tác vụ bị trì hoãn không
- Kiểm tra nhật ký hàng đợi để xác định nguyên nhân của sự cố

##13. Tóm tắt

Cơ chế tác vụ xếp hàng của hệ thống CRMEB cung cấp khả năng xử lý không đồng bộ mạnh mẽ. Thông qua việc sử dụng hợp lý các tác vụ hàng đợi, tốc độ phản hồi và tính đồng thời của hệ thống có thể được cải thiện và trải nghiệm người dùng có thể được cải thiện.Nhà phát triển có thể tạo các tác vụ xếp hàng tùy chỉnh dựa trên nhu cầu kinh doanh và triển khai nhiều logic xử lý không đồng bộ khác nhau.
