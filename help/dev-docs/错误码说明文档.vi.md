# Tài liệu mô tả mã lỗi CRMEB

## 1. Giới thiệu

### 1.1 Mục đích tài liệu
- Chuẩn hóa cách sử dụng mã lỗi trong hệ thống CRMEB
- Cung cấp tiêu chuẩn phân loại và định nghĩa mã lỗi
- Cung cấp hướng dẫn tham khảo xử lý lỗi cho lập trình viên
- Đảm bảo tính nhất quán và khả năng bảo trì của thông tin lỗi hệ thống

### 1.2 Phạm vi áp dụng
- Phát triển và bảo trì tất cả mô-đun của hệ thống CRMEB
- Xử lý lỗi giao diện API
- Xử lý lỗi hệ thống quản trị backend
- Xử lý lỗi ứng dụng di động

### 1.3 Định nghĩa thuật ngữ
- **Mã lỗi**: Mã số trong hệ thống dùng để định danh một loại lỗi cụ thể
- **Lớp ngoại lệ**: Lớp dùng để xử lý và ném lỗi
- **Đa ngôn ngữ**: Thông tin lỗi theo các ngôn ngữ khác nhau mà hệ thống hỗ trợ

## 2. Quy chuẩn thiết kế mã lỗi

### 2.1 Định dạng mã lỗi
- **Định dạng**: Chỉ gồm số, độ dài từ 3-6 chữ số
- **Ví dụ**: 400, 401, 400001, 400086 

### 2.2 Phân loại mã lỗi

| Phạm vi | Phân loại | Mô tả | Ví dụ |
|------|------|------|------|
| 100-199 | Thông tin nhắc nhở | Thông tin nhắc nhở chung | 100 |
| 200-299 | Phản hồi thành công | Yêu cầu được xử lý thành công | 200 |
| 300-399 | Chuyển hướng | Cần chuyển hướng | 301, 302 |
| 400-499 | Lỗi phía client | Lỗi từ yêu cầu của client | 400, 401, 403, 404 |
| 500-599 | Lỗi máy chủ | Lỗi nội bộ máy chủ | 500, 501, 503 |
| 400000-499999 | Lỗi nghiệp vụ | Lỗi logic nghiệp vụ cụ thể | 400086, 400087 |
| 600000-699999 | Lỗi hệ thống | Lỗi cấp hệ thống | 600001 |
| 700000-799999 | Lỗi bên thứ ba | Lỗi từ dịch vụ bên thứ ba | 700001 |

### 2.3 Quy tắc đặt tên mã lỗi
- Mã lỗi nên có ngữ nghĩa rõ ràng để dễ hiểu và ghi nhớ
- Mã lỗi trong cùng một mô-đun nên tập trung trong một dải
- Mã lỗi phải đảm bảo tính duy nhất, tránh trùng lặp

## 3. Cơ chế xử lý lỗi

### 3.1 Hệ thống lớp ngoại lệ

Hệ thống CRMEB sử dụng các lớp ngoại lệ sau để xử lý lỗi:

| Lớp ngoại lệ | Namespace | Mục đích |
|--------|----------|------|
| ApiException | crmeb\exceptions | Lỗi giao diện API |
| AuthException | crmeb\exceptions | Lỗi xác thực và phân quyền |
| AdminException | crmeb\exceptions | Lỗi quản trị backend |
| PayException | crmeb\exceptions | Lỗi liên quan thanh toán |
| CrudException | crmeb\exceptions | Lỗi thao tác CRUD |
| ApiStatusException | crmeb\exceptions | Lỗi API có kèm mã trạng thái |
| OAuthException | crmeb\services\oauth | Lỗi xác thực OAuth |

### 3.2 Cách ném lỗi

#### 3.2.1 Ném ngoại lệ trực tiếp
```php
// 使用错误信息
throw new ApiException('参数错误');

// 使用错误码
throw new ApiException(400086);

// 使用错误码和替换参数
throw new ApiException(400086, ['name' => '用户名']);

// 使用数组形式
throw new ApiException([400086, '参数错误']);
```

#### 3.2.2 Sử dụng trong validator
```php
protected $message = [
    'name.require' => '400086',
    'sort.require' => '400087',
    'sort.number' => '400088'
];
```

### 3.3 Lấy thông tin lỗi

Hệ thống dùng hàm `getLang()` để lấy thông tin lỗi, hỗ trợ đa ngôn ngữ:

```php
// 获取错误信息
$message = getLang($code, $replace);
```

## 5. Quản lý mã lỗi

### 5.1 Định nghĩa mã lỗi

Mã lỗi nên được định nghĩa tập trung trong file ngôn ngữ để dễ quản lý và hỗ trợ đa ngôn ngữ:

```php
// 语言文件示例
return [
    400001 => '用户名已存在',
    400002 => '手机号已被注册',
    // 更多错误码...
];
```

### 5.2 Phân bổ mã lỗi

- Mã lỗi nên được phân bổ theo từng dải riêng cho từng mô-đun
- Khi thêm mã lỗi mới cần tránh xung đột với mã lỗi hiện có
- Việc phân bổ mã lỗi nên được ghi lại trong tài liệu để tiện tra cứu

### 5.3 Bảo trì mã lỗi

- Kiểm tra định kỳ việc sử dụng mã lỗi
- Dọn dẹp các mã lỗi không còn sử dụng
- Thống nhất quy tắc đặt tên và mô tả mã lỗi

## 6. Thực hành tốt nhất khi xử lý lỗi

### 6.1 Xử lý lỗi phía frontend

1. **Thông báo lỗi thống nhất**: Sử dụng component thông báo lỗi thống nhất
2. **Ánh xạ mã lỗi**: Hiển thị thông tin lỗi tương ứng theo mã lỗi
3. **Thân thiện với người dùng**: Thông tin lỗi nên ngắn gọn, dễ hiểu
4. **Nhật ký lỗi**: Ghi log lỗi phía frontend để thuận tiện kiểm tra

### 6.2 Xử lý lỗi phía backend

1. **Xử lý theo tầng**: Mỗi tầng sử dụng lớp ngoại lệ phù hợp
2. **Log chi tiết**: Ghi log lỗi đầy đủ, gồm mã lỗi, thông tin lỗi, tham số yêu cầu...
3. **Tuân thủ quy chuẩn mã lỗi**: Sử dụng mã lỗi nghiêm ngặt theo quy chuẩn
4. **Bắt ngoại lệ**: Bắt ngoại lệ hợp lý để tránh hệ thống bị sập
5. **Quốc tế hóa thông tin lỗi**: Hỗ trợ thông tin lỗi đa ngôn ngữ

### 6.3 Khuyến nghị sử dụng mã lỗi

1. **Có ngữ nghĩa**: Mã lỗi nên có ý nghĩa để dễ hiểu
2. **Tính nhất quán**: Cùng loại lỗi nên dùng cùng một dải mã lỗi
3. **Khả năng mở rộng**: Dự trù đủ không gian mã lỗi cho mở rộng sau này
4. **Tài liệu hóa**: Cập nhật tài liệu mã lỗi kịp thời, đảm bảo đồng bộ với mã nguồn

## 7. Mở rộng mã lỗi

### 7.1 Mã lỗi tùy chỉnh

Lập trình viên có thể tùy chỉnh mã lỗi theo nhu cầu nghiệp vụ, theo các bước sau:

1. Xác định phạm vi và phân loại mã lỗi
2. Định nghĩa thông tin lỗi trong file ngôn ngữ
3. Sử dụng mã lỗi trong mã nguồn
4. Cập nhật tài liệu mã lỗi

### 7.2 Quản lý phiên bản mã lỗi

Khi nâng cấp phiên bản hệ thống, việc quản lý mã lỗi cần lưu ý:

1. Giữ tương thích ngược: tránh thay đổi ý nghĩa mã lỗi hiện có
2. Thêm mã lỗi mới: thêm trong phạm vi đã dự trù
3. Loại bỏ mã lỗi: đánh dấu các mã lỗi không còn sử dụng

## 8. Câu hỏi thường gặp

### 8.1 Mã lỗi bị trùng

**Vấn đề**: Các mô-đun khác nhau sử dụng cùng một mã lỗi

**Giải pháp**:
- Phân bổ dải mã lỗi theo từng mô-đun
- Thiết lập cơ chế quản lý mã lỗi
- Kiểm tra định kỳ tình trạng sử dụng mã lỗi

### 8.2 Thông tin lỗi không rõ ràng

**Vấn đề**: Thông tin lỗi chưa đủ rõ, khó hiểu

**Giải pháp**:
- Thông tin lỗi nên ngắn gọn, dễ hiểu
- Thông tin lỗi nên nêu rõ nguyên nhân cụ thể
- Thông tin lỗi nên dễ hiểu với người dùng

### 8.3 Xử lý lỗi không nhất quán

**Vấn đề**: Cách xử lý lỗi giữa các mô-đun không thống nhất

**Giải pháp**:
- Thống nhất cơ chế xử lý lỗi
- Sử dụng lớp ngoại lệ thống nhất
- Tuân thủ các thực hành tốt nhất khi xử lý lỗi

## 9. Tổng kết

Mã lỗi là thành phần quan trọng trong hệ thống, thiết kế và sử dụng mã lỗi hợp lý có thể nâng cao khả năng bảo trì hệ thống và trải nghiệm người dùng. Tài liệu này cung cấp quy chuẩn thiết kế, cách sử dụng và thực hành tốt nhất cho mã lỗi trong hệ thống CRMEB, hy vọng có thể giúp lập trình viên hiểu và sử dụng mã lỗi hiệu quả hơn.

Trong quá trình phát triển thực tế, lập trình viên nên tuân thủ nghiêm ngặt các quy chuẩn trong tài liệu này để đảm bảo tính nhất quán và khả năng bảo trì của mã lỗi. Đồng thời, cần liên tục hoàn thiện và mở rộng hệ thống mã lỗi theo nhu cầu nghiệp vụ để thích ứng với sự phát triển và thay đổi của hệ thống.

> **Gợi ý**: Tài liệu này được AI tạo ra, chỉ mang tính tham khảo.
